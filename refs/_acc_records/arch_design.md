# LENS THESES + OBJECTIONS

## COMPETITIVE (benchmark vs SOTA: commercial trend tools, agen
THESIS: refcap는 SOTA 트렌드툴(VidIQ/Pentos류 "메트릭만")과 에이전트 파이프라인(이해는 좋으나 "그럴듯한 합성, 출처 0")의 가운데가 비어있는 지점 — verbatim 콘텐츠를 가진 cite-or-fail provenance bottom — 을 이미 점유하고 있다. 진짜 경쟁자라면 R/O/E를 LLM 자유생성이 아니라 "결정형 라우팅 + 타입드 evidence claim + Merkle 봉인 + 누적 코퍼스"로 만든다. 따라서 빠진 3조각은 신규 거대 의존성 없이 refrecord의 검증된 게이트 어휘를 상위로 끌어올리는 ~3개 소형 파일(refroute.py / refpipe.py / refevidence.py)로 구현하고, 차별점은 "모든 분석 라인이 hash-등록된 transcript_cue/frame/text_span 앵커에 묶여 재검증 가능"이라는 가드레일에 집중한다. 에이전트의 자유 분석(FRAMEWORK 23항목)은 유지하되 그 출력을 게이트 통과 가능한 claim으로 강제하는 것이 SOTA 대비 방어선이다.
OBJECTION: 가장 강한 반론 (정직하게, 다른 렌즈와 충돌): **"라우터를 코드로 박는 건 에이전트(나)가 이미 더 잘하는 일을 더 나쁘게 자동화하는 것 — 표면적 라우팅은 흡수당한다."** harness-durability 메모리의 결론과 정면충돌한다: scaffolding(라우팅 규칙 같은 결정-스택)은 프론티어 모델에 흡수되고, durable한 건 cage(결정론 바닥)뿐이다. refroute의 if-else 임계값 라우터는 모델이 frames+transcript를 직접 보고 "이건 음악몽타주"라 판단하는 것보다 brittle하다(임계값 튜닝 지옥, 경계 케이스 오분류). 즉 R은 SOTA 대비 **앞서는 게 아니라 오히려 모델 능력의 그림자**일 수 있다.

이 반론에 대한 내 입장(밀어붙임): R의 가치는 "정확도"가 아니라 **재현성·감사추적**이다. 에이전트 라우팅은 매번 다를 수 있고 "왜 transcript 경로를 골랐나"를 사후 증명 못 한다. refroute는 rationale 필드로 "gate=NO_SPEECH & ocr<3가 montage를 결정"을 기록 — 이게 E(증거)층과 한 몸이 되어야 의미가 산다. 따라서 R은 **독립 가치가 약하고, E에 종속될 때만 정당화된다**. R을 단독 셀링포인트로 마케팅하면 안 된다(STOP 신호와 일치). 진짜 durable한 조각은 R도 O도 아닌 **E(cite-or-fail 봉인)** 하나뿐이다 — 나머지 둘은 E를 먹이기 위한 결정형 골격일 뿐.

2차 리스크: farm 호출을 에이전트 seam에 둔 설계는 "결정형 오케스트레이터(에이전트 없이 돎)" 요구와 부분 충돌 — 봉인의 마지막 마일(add_claim/gate)은 결국 에이전트가 돌린다. MCP 서버가 스킬을 못 부르는 구조적 제약이라 우회 불가지만, "완전 무인 봉인"은 이 아키텍처로 불가능하다는 걸 정직히 인정한다.
DO_NOT_BUILD: YAGNI — 만들면 안 되는 것:

1. **LangGraph/DSPy 실제 의존성 도입 금지.** 그 패턴(명시적 state, 결정형 전이, 체크포인트)만 ~150줄로 차용. 거대 그래프 런타임은 deps 제약·메모리 제약 위반이고 단일 직선 파이프라인엔 과잉.

2. **LLM 라우터 노드 금지.** route()는 순수 규칙함수로 유지. LLM 라우터는 비결정·재현불가 = refcap의 차별점(감사추적)을 죽인다.

3. **소스-내비게이션/셀렉터 스택, multi-vantage·TLS 헤드라인 마케팅 금지** (harness-durability STOP 신호). refcap은 콘텐츠 이해 도구지 브라우저 자동화 farm이 아니다 — 중립성 유지.

4. **벡터DB/임베딩 검색 누적 코퍼스 금지.** index.jsonl(append-only JSONL)로 충분. 임베딩은 신규 대형 의존성+메모리. evidence-RAG의 "인덱스"는 jsonl grep으로 80% 달성, 나중 필요시에만.

5. **refcap을 farm 안으로 이동 금지.** farm을 import하지 말고 매니페스트 seam만. 중립성 = "이해엔진은 farm 밖, 봉인엔진은 farm" 분리 유지.

6. **새 ASR/OCR/분리 모델 도입 금지.** refrecord의 medium/large-v3/htdemucs_ft 검증된 스택 그대로. 동시 로드 금지(OOM) 규칙도 유지 — refroute가 tier-2 비용을 게이트로 결정하므로 모델 추가 불필요.

7. **R의 6번째 content_type 추가 금지** (현재 5종이면 FRAMEWORK 커버 충분). 경계 임계값 튜닝은 실측 오분류가 나온 뒤에만.

## CRITICAL / 적대적 (over-engineering·YAGNI·깨지는 규칙·farm 커플링 위험 공격
THESIS: 세 조각 중 둘(R 콘텐츠-타입 라우터, O 결정형 오케스트레이터)은 대부분 YAGNI다 — refcap의 "두뇌"는 에이전트이고, 코드가 이미 가진 결정 지점은 process_wav/coverage_gate 안의 음향-품질 게이트뿐이며 그게 옳다. 진짜로 빠진 유일한 조각은 E(증거 라이브러리)이고, 그조차 farm을 "검증기"가 아니라 "공증인(byo-transcript notary)"으로만 써야 한다. 따라서: R은 만들지 말고(에이전트가 라우팅), O는 기존 process_wav를 얇게 확장만 하며(새 오케스트레이터 신설 금지), E만 신규 모듈로 짓되 순수 부가·실패-격리·옵트인으로 짓는다.
OBJECTION: 가장 강한 자기-반론(이게 내 입장의 최대 리스크): "에이전트가 두뇌"라는 게 영원히 옳지 않을 수 있다 — 사용자가 refcap을 *배치*로(에이전트 없이 100개 영상) 돌리고 싶어지면 결정형 R/O가 정말 필요해진다. 그 시나리오에선 내 "라우터 만들지 마라"가 병목. 반박의 반박: 그래도 R/O를 *선제적으로* 짓는 건 YAGNI다 — 배치 욕구가 실제로 생기면 그때 coverage_gate 출력을 if-else로 묶는 30줄이면 되고, 그건 이미 process_wav 안에 결정형으로 존재한다(247-299). 둘째 리스크: farm 커플링. farm 스키마(sourceUrl uri 필수, evidenceKind enum 고정)가 바뀌면 E 층2가 깨진다 — 그래서 층1(seal_local)을 farm-독립으로 못박은 것이고, farm은 *에이전트 런북*에만 의존하므로 refcap 코드는 farm 변경에 면역이다. 셋째(가장 정직한): cite-or-fail은 fabrication-at-capture를 못 막는다 — whisper가 환각한 전사를 farm은 충실히 해시·앵커한다. 즉 E는 "이 바이트가 그때 그랬다"는 증명이지 "이 전사가 맞다"는 증명이 아니다. 이걸 사용자에게 과대광고하면 안 된다(MEMORY의 "열린 지붕"). E의 진짜 방어선은 coverage_gate/degeneracy(refrecord.py)가 환각을 *캡처 전에* NO_SPEECH/DEGENERATE로 라벨링하는 것 — 그게 refcap의 moat이고 farm은 그 다음의 공증일 뿐이다.
DO_NOT_BUILD: 절대 만들면 안 되는 것: (1) 신규 router.py — 콘텐츠 타입을 판정하려면 전사/OCR을 이미 해야 하므로 절감 동기가 거짓이고, 장르→파이프라인 정적 매핑은 LLM 유연성을 깨지는 임계값으로 격하시킨다(refrecord.py degeneracy의 gyeongju_food 오탐 주석:88-90이 임계값이 얼마나 잘 깨지는지의 증거). (2) 신규 톱레벨 오케스트레이터/상태머신/DAG — 메모리 OOM(15GB, refextract.py:131·refocr.py:20)을 부르고, farm MCP는 파이썬에서 호출 불가(에이전트 세션 소유)라 "자동 farm까지 도는 결정형 파이프"는 물리적으로 불가능. (3) refauto.py에 분기 추가 — 분기 0이 한글경로·인코딩·OOM 함정 면역의 핵심. (4) farm을 refcap 코드가 직접 import/호출 — 중립성 파괴 + 커플링; farm 접점은 에이전트 런북(docs)으로만. (5) raw 미디어 누적(audio.wav/vocals.wav를 KEEP) — don't-hoard 위반; 해시-지문만 evidence.json에 누적. (6) farm을 "전사 검증기"로 마케팅 — fabrication-at-capture를 못 막으므로 거짓 안전감(MEMORY 열린 지붕). (7) 동시 모델 로드를 허용하는 어떤 병렬화 — 현재 subprocess-OCR/del+gc 순차성이 OOM 방어선.

## creative
THESIS: refcap already contains its own router — coverage_gate() (refrecord.py:147) probes cheap audio byproducts (rms/voiced_sec/no_speech_prob/degeneracy) and emits a discrete status that branches the pipeline. The three "missing" pieces are not new subsystems; they are the SAME gate-pattern lifted one altitude: (R) a content-type router is a pre-probe gate over cheap signals refextract ALREADY computes (scene-change frame count, OCR line/char density, color saturation, audio coverage) — emergent, no classifier, no model; (O) the orchestrator is not code but a declarative content-addressed manifest (a recipe.json keyed by router verdict) that a ~60-line deterministic runner walks; (E) the evidence library is content-addressed by the SHA-256 the farm already computes — the hash IS the filename, so dedupe and tamper-evidence are the same act, and don't-hoard dies because you keep only hash-named small artifacts, never raw media.
OBJECTION: The strongest objection to the CREATIVE design is the chicken-and-egg in the router and the latency tax it implies. To ROUTE a clip you need its probe vector, but two of the most discriminating probes (vo_cov, vo_status) require running ASR first — and the whole point was to AVOID wasting the expensive ASR on a music montage with no VO. So the "cheap pre-probe" isn't free: you must run a medium-model pass on EVERY clip just to discover it had no speech, which is exactly the cost the router was supposed to save. The creative framing ("router emerges from cheap probes") partly oversells: rms+scene_rate+ocr are genuinely cheap, but vo_cov is not. Mitigation that keeps the thesis honest: gate the ASR itself on the truly-cheap probes first — if rms<floor OR (scene_rate>=hi AND ocr_lines>=hi suggesting a text/music montage), route to MUSIC/TEXT/SILENT BEFORE spending the medium pass, and only run probe_asr when the cheap signals don't already decide. That makes the router a two-tier gate (cheap-probe gate -> conditional ASR -> full route), which is more faithful to coverage_gate's own "escalate only when flagged" philosophy than the flat version. Second objection: content-addressing by the farm's hash assumes the farm is reachable and trustworthy as a notary for a tool that is supposed to live OUTSIDE the farm; if the farm is down, seal() must degrade to a local sha256 (stdlib hashlib, no new dep) so the library never blocks on farm availability — the farm upgrades a local hash to a Merkle bundle, it is not a hard dependency.
DO_NOT_BUILD: DO NOT BUILD: (1) An ML content-type classifier / embedding model / scene-detection NN. The whole creative bet is that thresholded cheap probes over EXISTING byproducts beat a learned classifier for a 5-bucket decision — adding a model violates the 15GB/no-concurrent-load OOM constraint and the zero-new-dep rule, and is unbenchmarkable against the existing gate. (2) A general workflow ENGINE (DAG executor, retries, conditionals-as-code, plugin system). recipes.json is a FLAT lookup table (verdict->channels), not a Turing-complete pipeline language; the moment it grows if/else it has become the agent-in-code it was meant to replace. The deterministic walker must stay ~60 lines. (3) A second hashing/Merkle implementation inside refcap — let the farm be the notary; only fall back to stdlib hashlib for offline degrade, never reimplement Merkle/Ed25519. (4) Hoarding raw media in the library "just in case" for re-analysis — content-addressing means re-download is idempotent and the raw bytes are reproducible from the URL; keep ONLY hash-named derivatives. (5) Auto-running farm_add_claim on EVERY transcript line — claims are the AGENT's load-bearing assertions (hook lever, transferable mechanic), not boilerplate; spraying claims defeats cite-or-fail by drowning the gate. (6) A router verdict that mints a transcript_cue channel for MUSIC_MONTAGE/SILENT_VIBE — that would let the agent fabricate VO the clip never had, destroying the one durable property (honest absence) that coverage_gate already guarantees.

## productive
THESIS: R/O/E의 신호는 이미 파이프라인 부산물로 존재한다(gate status, 프레임 prefix별 개수, OCR line수, rms, vocal_energy_ratio). 새 분류기·새 프로브 패스·새 대형의존성 0으로, 이 부산물을 "읽기만" 하는 얇은 결정 함수 3개를 추가하면 즉시 돈다. R=process_wav 이후의 사후-라우터(분기 없는 직선 실행은 유지, 라우팅은 "에이전트가 무엇을 읽어야 하나"를 결정), O=refextract를 한 함수로 승격(이미 70% 오케스트레이션됨), E=refextract 끝에 farm MCP를 옵션 호출하고 here/refs를 content-addressed 라이브러리로 만들되 raw는 계속 버린다(증거=해시+요약 JSON, raw≠증거).
OBJECTION: 가장 강한 반론: 라우터가 gate-status를 재활용하는데, gate는 "ASR 커버리지"를 측정하지 "콘텐츠 타입"을 측정하지 않는다. clean-VO인데 BGM이 세서 COVERAGE_GAP이 뜬 영상과, 진짜 음악몽타주는 둘 다 같은 status를 줄 수 있어 route가 오판할 수 있다(예: tier-2가 VO를 건졌는데도 before-gate status로 라우팅하면 MUSIC로 잘못 분류). 완화: route_clip에 tier-2 recovery 결과(res["recovery"]["after"])를 우선 사용 — recovery가 helped면 after.status로 라우팅. 두 번째 리스크: route는 결국 에이전트에게 "읽기 가이드"일 뿐, 에이전트가 무시하면 효과 0(라우터의 출력이 강제력 없음). 이건 의도된 트레이드오프 — 결정형 강제 분기는 깨지기 쉽고(critical 렌즈 지적), refcap의 두뇌는 여전히 에이전트다. 라우터는 에이전트를 대체하지 않고 "무게중심 라벨"로 보조만 한다. 세 번째: scene_rate가 ffmpeg scene-select 프레임 수에 의존 — 짧은 클립/저해상도에서 노이즈. 버킷(low/med/high)으로만 쓰고 절대값 신뢰 안 함으로 완화.
DO_NOT_BUILD: 절대 만들지 말 것(YAGNI): (1) ML 콘텐츠-타입 분류기/임베딩 — 신호는 이미 부산물로 충분, 새 모델=메모리+의존성 폭탄(15GB OOM). (2) LangGraph/DSPy/그래프-엔진 오케스트레이터 — refextract는 직선 7단계, 함수 하나면 됨. 선언적 manifest/DAG도 과설계. (3) 조건부 추출(라우터가 먼저 분류해서 일부 추출 스킵) — frames/OCR/색은 다 싸거나 이미 돈다; 스킵해서 아끼는 건 거의 없고 잘못 분류하면 데이터 손실. 다 뽑고 라벨만 붙여라. (4) refcap 내부에서 farm MCP를 직접 호출하는 브리지(HTTP 클라이언트/서브프로세스) — 중립성 깨고 커플링 생김; farm_plan.json으로 "레시피만" 넘기고 실행은 에이전트. (5) raw 영구보관(증거라이브러리 명목으로 wav/대형프레임 hoard) — 해시만 보관, raw는 계속 버림. (6) video sha256를 위한 전체 영상 재해시를 매번 — 이미 dl/에 있을 때만, content-addressed dedupe는 nice-to-have이지 P1 아님.


# ===== SYNTHESIS =====

## architecture_1para
refcap stays the understanding engine; the farm stays the notary. The three missing pieces are NOT new subsystems — they are the BENCHMARKED gate vocabulary (refrecord.coverage_gate -> NO_SPEECH_OR_MASKED / SILENT / COVERAGE_GAP / LOW_CONFIDENCE / OK / DEGENERATE) lifted one altitude, plus a content hash, plus an append-only index. Concretely: (E) one new stdlib-only file refevidence.py seals every run by hashing the small derivatives (transcript/color/ocr/meta/keyframes) BEFORE the existing raw-audio delete, writes evidence.json + a farm_plan.json (a SHAPED list of farm_* calls the agent/.mjs executes — refcap never imports farm), and appends one line to a designated library index; (R) one new stdlib-only function refroute.route() is a POST-HOC reading-guide (NOT a pre-classifier, NOT a skip-gate) that reads the gate status the pipeline ALREADY produced and labels the analysis center-of-gravity + the claimable_channels allow-list (a MUSIC_MONTAGE structurally cannot mint a verbatim-VO claim, mirroring the gate's honest NO_SPEECH); (O) refextract's already-linear 7 steps are promoted into ONE pure function analyze_video() (refauto becomes a thin wrapper) with colorprofile wired in as the missing auto-step — no state machine, no DAG, no agent in the loop for the deterministic part. The agent remains the brain for FRAMEWORK.md analysis, but every load-bearing analysis line must pass through farm_add_claim (cite-or-fail) before it enters the Merkle bundle. E is the only durable piece; R and O exist only to feed E. Zero new dependencies; zero concurrent model loads.

## router_concrete
FILE/FN: refroute.py, `route(coverage: dict, frames: list[str], ocr_meta: dict, rms: float, dur: float, color: dict) -> dict`. deps=0 (pure dict logic + glob/len). NOT a separate pre-classifier — it runs AFTER process_wav, reading signals the pipeline ALREADY emitted (no extra decode, no extra model). 

PROBE SIGNALS (all existing byproducts): coverage = res["coverage"] (the gate dict: status, coverage_ratio, voiced_sec, n_segments); rms (refextract.py:74); scene_rate = (count of frames starting "scene_")/dur (just glob+len of the scene_*.jpg ffmpeg already wrote at refextract.py:53); ocr_lines = ocr_meta["lines"] (already recorded refextract.py:91); saturation/contrast_Vstddev from the NEW color.json.
