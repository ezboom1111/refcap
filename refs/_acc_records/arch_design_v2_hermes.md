# LENS THESES (vs hermes)

## COMPETITIVE
THESIS: "증거 척추가 차별점"은 *맞지만 좁다*: hermes에 provenance 플러그인 하나로 흡수되지 않는 부분은 오직 **bind-at-capture + deterministic byte-gate(작은 TCB)** 뿐이고, ledger/state/frontier는 흡수된다. 그러므로 척추를 풀스택으로 짓지 마라 — ingest(얇은 라우터)+evidence-ledger(이미 있는 farm 일반화)만 코드로 박고, research-state/memory/skill-learning은 hermes(또는 Claude Code 자체)에 위임하라. 진지한 경쟁자는 척추를 "검증 커널 + 호스트의 메모리에 얹는 어댑터"로 짓지, 자체 메모리 제국으로 짓지 않는다.
VS_HERMES: **차용**: hermes의 hermes_state.py(세션 상태)+FTS5 세션검색+LLM 요약 cross-session recall+skills/(agentskills.io 표준=Claude Code skill과 동일계열)는 내 제안 research-state/ledger보다 훨씬 성숙하다. 내 state.json(frontier/open-questions/visited)을 직접 구현하면 hermes 메모리의 빈약한 재발명이 된다 → 차용/위임이 맞다. **중복(짓지 마라)**: 내가 처음에 그린 "research_<goal>/state.json + frontier 관리 + 재개"는 hermes_state.py와 99% 중복. cross-session recall, 유저모델링, skill 자가개선도 전부 중복. **차별(durable moat)**: hermes에 *전혀 없는* 것 = ① capture 시점의 origin-binding(bind-at-capture, capture-transcript.ts의 binds:{path,sha256}), ② 결정론적 byte-gate(claim-gate.ts, 모델 신뢰 0), ③ 상류 coverage_gate(refrecord.py: NO_SPEECH/DEGENERATE를 *캡처 전에* 라벨링 — fabrication-at-capture를 모델이 아닌 음향통계로 잡음), ④ Merkle 번들(farm_export_bundle, 제3자 재검증). **흡수 위험(정직하게)**: hermes가 "각 도구 출력에 sha256 + source_url 한 줄 + 인용 검사기"를 붙이면 내 ledger층의 80%는 흡수된다. 흡수 *안 되는* 20% = bind-at-capture와 작은 TCB(claim-gate가 LLM을 한 번도 호출 안 하고 deps 거의 0). 왜냐면 hermes의 가치제안은 portability/no-lock-in/closed-loop learning이라 "결정론적이고 외부감사 가능한 작은 커널"은 그들의 철학과 *상충*한다(그들은 큰 통합 두뇌를 원함). 그래서 차별점은 기능이 아니라 **TCB 크기와 중립성**이라는 아키텍처적 입장에 산다. STOP: state/memory/skill을 자체 구현하는 순간 hermes와 정면충돌 → 패배(그쪽이 18개월 앞섬).
BRAIN_BOUNDARY: 코드로 박는 것(결정론, LLM 호출 0): ① ingest 타입감지+dispatch(매직바이트/확장자 — 순수 규칙, 임계값 없음), ② sha256 재해시(claim-gate.ts L660), ③ byte-grounding(quote가 artifact 바이트에 literal 존재? L386), ④ 독립소스 카운트(independentSourceGroups), ⑤ provenance 체인 강제(requiredDestinationProvenanceKinds), ⑥ 상류 coverage_gate(refrecord: 음향통계로 NO_SPEECH/DEGENERATE — 이건 *모델 출력을 못 믿으니까* 음향 RMS/logprob/repetition으로 캡처 전 판정). 에이전트(두뇌)에 맡기는 것: ① "조사하라"→무슨 데이터/소스 분해, ② frontier 우선순위(다음 ingest 타깃), ③ 비정형↔정형 전환 시 전략 적응, ④ claim 텍스트 작성+anchor 선택, ⑤ 종료 판단(open-questions 소진). **경계의 사상: 코드는 "거짓말을 못 하게"만, 두뇌는 "무엇을 조사할지"를. gate는 hallucination(인용 없는 주장)을 막지만 fabrication-at-capture(모델이 전사 바이트 자체를 조작)는 못 막는다 — 그 구멍은 코드(상류 coverage_gate)로만 닫지, 더 똑똑한 에이전트로는 못 닫는다. 이게 hermes가 영원히 못 따라오는 지점: 그들의 두뇌는 더 똑똑해질 뿐, 자기 출력을 *불신*하는 음향 커널이 없다.** 안티패턴 확정: 깊은 분석/라우팅 판단을 코드 임계값 결정트리로 박지 마라(degeneracy() L88의 gyeongju false-positive가 산 증거 — 0.25 임계값이 좋은 여행리스트를 오탐). 얕은 dispatch만 코드.
OBJECTION: **가장 강한 반론(흡수): "hermes에 도구 출력마다 sha256+source_url 한 줄 추가 + 인용 검사기 하나 = 너의 ledger층 흡수, 게다가 그쪽은 메모리/learning까지 있으니 우월."** 이 반론은 *80% 맞다*. ledger/citations/state는 흡수된다. 정직하게 인정한다. 살아남는 20%의 방어선은 기능이 아니라 *아키텍처 입장*이다: ① **bind-at-capture** — sha256를 "도구가 출력을 받은 뒤" 찍는 것과 "캡처 경로가 바이트를 받는 순간" 찍는 것은 다르다. hermes는 전자(모델/도구가 이미 만질 수 있는 바이트에 사후 해시) → fabrication-at-capture에 무방비. refcap은 후자에 근접(coverage_gate가 ASR 출력을 *음향통계로 불신*). ② **작은 TCB+중립성** — claim-gate가 LLM 호출 0, deps 거의 0이라 제3자가 `farm_verify_bundle`로 독립 재검증 가능. hermes의 "큰 통합 두뇌+자체 메모리"는 검증자가 그 두뇌를 신뢰해야 함 → 감사 불가. **그러나 이 20%조차 소켓/네트워크 플랫폼(예: 캡처를 OS/프록시 레벨에서 하는 자)이 더 잘한다**(전 세션 합의: origin-bound capture attestation은 소켓이 우월). 따라서 *유일하게 진짜 durable한 것* = "중립적이고 작은, 외부감사 가능한 검증 커널"이라는 포지션 자체. 기능 경쟁으로 가면 진다. STOP 신호: 누가 ledger에 sha256를 붙이는지로 싸우기 시작하면 이미 졌다 — 싸움터를 "bind 시점 + TCB 감사가능성"으로 옮겨야 한다.
DO_NOT_BUILD: ① **research-state/state.json/frontier 자체 구현 금지** — hermes_state.py와 99% 중복, 그쪽이 18개월 앞섬. 호스트에 위임. ② **cross-session 메모리/FTS5 검색/유저모델링 금지** — hermes 핵심 강점, 재발명은 패배. ③ **skill 자가개선 learning-loop 금지** — agentskills.io 표준(=Claude Code skill)이 이미 있고 hermes가 성숙시킴; refcap 스킬은 그 표준의 *소비자*로 남아라. ④ **ingest 안에 임계값 결정트리/점수 라우팅 금지** — degeneracy() gyeongju 오탐이 증거. dispatch는 매직바이트/확장자 규칙만, 깊이 0. ⑤ **farm이 "다음에 뭘 조사할지" 결정하는 로직 금지** — 중립성 파괴(farm은 register하면 검증만; MCP 서버는 스킬/두뇌를 호출 못 함). ⑥ **멀티소스 "의미적 일치" 판정을 코드로 금지** — claim-gate는 byte-presence/독립도메인 카운트까지만(L399 주석이 명시), semantic agreement는 caged-judge(외부 LLM)에 위임. ⑦ **TikTok/IG 자동취득·쿠키/anti-bot 우회 절대 금지**(ToS) — ingest는 이미 서빙된 것/공식 API/사용자 제공 파일만. ⑧ **새 무거운 의존성 금지**(15GB OOM, 동시 대형모델 로드 금지) — html ingest는 stdlib/trafilatura 수준, 새 ML 모델 추가 금지.

## CRITICAL / 적대 (red-team)
THESIS: "척추를 새로 짓자"는 hand-waving이다. ingest/ledger/state 3종 중 ledger는 farm에 이미 있고(register_evidence는 영상 아닌 임의 artifact를 SHA256+provenance로 등록함 — 일반화는 이미 끝났다), state는 에이전트 컨텍스트+파일시스템의 재구현이며, uniform ingest는 refauto 위의 불필요한 인디렉션이다. 정당한 신규 코드는 단 하나: 여러 소스를 한 목표 아래 묶고 재개 가능하게 하는 ~120줄짜리 research-manifest 인덱스(refindex.py). 나머지는 만들면 안 된다.
VS_HERMES: hermes는 "두뇌=에이전트" 재구성을 지지하지만(LLM loop + skills + state, 판단 로직을 코드에 안 박음), 동시에 이 제안의 state/ledger를 *치명적으로 흡수 위협*한다. hermes_state.py + FTS5 세션검색 + MEMORY.md/USER.md + agentskills.io 호환 skills는 내 제안 "research-state(frontier/visited/open-questions)"의 *성숙한 상위집합*이다. 즉 내가 state.json을 새로 지으면 hermes(또는 Claude Code 자체 메모리)의 얇고 열등한 클론을 짓는 것이다 — 흡수 위험 명백. 반대로 hermes가 *구조적으로 못 가진* 것은 단 하나: 해시 등록 + cite-or-fail 게이트(WebFetch로 확인, README에 provenance/verification 단어 0개, audit는 학습용 trajectory 압축이지 증거가 아님). 따라서 정직한 위치는: state/memory/skill/learning-loop는 hermes(혹은 Claude Code)에게 양보하고 절대 재구현하지 말 것. refcap이 방어 가능한 유일한 표면 = claim-gate.ts의 결정론적 cite-or-fail + 상류 coverage_gate의 캡처전 환각 라벨링. 척추 전체를 짓는 게 아니라 *증거 척추만* 짓는다 — 그리고 그건 이미 80% 지어져 있다.
BRAIN_BOUNDARY: 경계를 칼같이: 코드에 박는 것 = (a) 결정론적 무엇 — SHA256, JSONL append, manifest 인덱싱, coverage_gate/degeneracy(이미 측정·튜닝 완료된 캡처전 라벨), WebVTT 파싱. 즉 "바이트가 존재하고 변하지 않았다"와 "캡처가 환각인가"의 기계적 판정만. 에이전트에 맡기는 것 = 무엇을 조사할지, 어떤 소스로 갈지, 정형 보다 비정형이 튀어나왔을 때 전환할지, frontier에서 다음 무엇을 pop할지, 언제 충분한지 — 모든 *전략과 적응*. 핵심 경계선 한 문장: "코드는 증거가 진짜인지(존재+불변+캡처품질)만 판정하고, 무엇이 증거가 될지·어떻게 모을지는 절대 판정하지 않는다." 사용자의 불만("스킬에 두뇌가 없어")의 올바른 해석 = 두뇌를 추가하는 게 아니라, refauto의 *직선 파이프라인*(line 19-27, url 하나→extract 하나→끝)을 에이전트가 루프 안에서 여러 번 호출하며 결과를 manifest에 누적하도록 *열어주는* 것. 즉 빠진 건 brain도 spine도 아니라 *루프를 막고 있는 직선성*이다. refauto를 "한 번 실행하고 끝"이 아니라 "에이전트가 N번 호출 가능한 멱등 추출기"로 만들면 두뇌(에이전트)가 알아서 깊이 판다.
OBJECTION: 최대 리스크 두 가지. (1) cite-or-fail의 가치가 정말 뭔가 — 정직한 답: 이미 합의된 한계 그대로다. claim-gate.ts의 normalizeForMatch(line 575)는 lowercase+whitespace만 정규화하고 includes()로 부분문자열 매칭한다. 이건 "모델이 인용한 텍스트가 등록된 바이트에 존재한다"만 증명하지 "그 바이트(전사)가 정확하다"는 증명하지 못한다. fabrication-at-capture(모델이 환각 전사를 register_transcript로 넣음)는 게이트를 그대로 통과한다 — 등록된 바이트 안에 있으니까. 따라서 *척추(ledger+게이트)의 가치는 hallucination-at-cite는 막지만 fabrication-at-capture는 못 막는, 좁은 것*이다. 진짜 moat는 척추가 아니라 *상류 refrecord의 coverage_gate*가 환각을 NO_SPEECH/DEGENERATE로 캡처전에 라벨링하는 것이다(이게 fabrication을 줄이는 유일한 실제 메커니즘). 그러므로 "척추를 짓자"에 에너지를 쓰는 건 우선순위 오류 — 이미 있는 게이트보다 coverage_gate 류의 캡처전 품질 라벨을 fetch/ocr 경로로 *확장*하는 게 훨씬 값지다. (2) rabbit-hole — manifest에 visited만 있고 frontier/depth-budget을 코드가 강제하지 않으면 에이전트가 무한히 판다(메모리/$0 위반). 하지만 이걸 코드로 막으면(depth>=N이면 stop) 또 임계값 트리다. 절충: 코드는 *count만 노출*하고(state.collected), 멈춤은 에이전트가 — 단 refauto에 동시성 가드(대형모델 1개만 로드, refrecord line 132 gc 패턴)는 코드로 박아 OOM만 결정론적으로 막는다.
DO_NOT_BUILD: 절대 만들면 안 되는 것(우선순위순): (1) uniform `ingest(thing)` 추상화/타입디스패처 클래스 — refauto의 if/elif 6줄을 "프리미티브"로 격상하는 순간 ingest 안에 타입감지 두뇌가 기어들고, 그게 바로 gyeongju 오탐을 낳은 코드-에 박힌-판단의 재림. (2) frontier/open-questions를 코드가 *결정*하는 research-state 머신 — pop/push/우선순위를 코드가 정하면 임계값 트리 지옥. 에이전트가 컨텍스트로 들고 가게 두라. (3) hermes/Claude Code 메모리의 클론(FTS5 세션검색, cross-session recall, 유저모델링, skill 자가개선 learning-loop) — 흡수 위험 100%, 열등한 재구현. 이건 호스트 에이전트에게 양보. (4) depth-budget/rabbit-hole 임계값을 코드로 강제(에이전트가 count 읽고 판단). (5) farm을 refcap이 호출(중립 깨짐 — refindex는 farm import 0). (6) raw 비디오/오디오를 manifest나 research/ 디렉터리로 복사(don't-hoard 위반; 해시만). (7) "정형 중 비정형 나오면 ingest가 흡수" — 이건 코드가 흡수하는 게 아니라 에이전트가 다음 추출기를 고르는 것; ingest에 적응 로직을 넣지 말 것. (8) cite-or-fail이 fabrication을 막는다는 마케팅 — 막지 못한다, 좁은 hallucination-at-cite만. 신규 코드 총량 = refindex.py 1개(~120줄) + refauto.py에 --goal 한 줄. 그 이상은 전부 과설계.

## CREATIVE
THESIS: refcap에 필요한 건 brain이 아니라 SPINE이고, 그 척추는 세 개의 append-only 파일(content-addressed ledger + frontier-as-data state + cite-or-fail claims)과 단 하나의 라우터 함수 ingest()다. ingest가 타입을 sniff해 기존 추출기로 dispatch하면 "정형 중 비정형 출현"은 코드 분기 없이 흡수되고, 해시를 정체성으로 승격하면 dedupe·변조방지·재개가능성이 한 번의 sha256으로 떨어진다 — 두뇌는 Claude Code 루프에 그대로 둔다.
VS_HERMES: 차용: hermes의 SQLite SessionDB(sessions/messages/FTS5/parent_session_id 압축체인)는 cross-session recall에서 내 state.json보다 압도적으로 성숙하다 — frontier 큐만 영속화하는 내 척추는 그 얇은 버전이 맞다. 정직하게: 대화기억·skill자가개선은 hermes가 이긴다, 흉내내지 마라. 차별: hermes는 SessionDB 어디에도 provenance/content-hash/frontier/open-questions/cite-or-fail이 *없다*(1차 소스로 확인 — sessions/messages 테이블에 source_url도 sha256도 frontier도 없음). hermes의 audit는 *학습용 trajectory 압축*이지 검증증거가 아니다. 내 척추의 유일한 존재이유 = 그 빈칸. 흡수위험: hermes가 skills/(agentskills.io)를 가졌으니 refcap을 그 표준 skill로 *합치면* hermes의 두뇌+기억 위에 내 증거척추가 plug-in으로 얹힌다 — 경쟁이 아니라 보완. 중복위험: state.json에 대화로그까지 욱여넣으면 hermes SessionDB와 정면충돌하고 진다. 그러므로 state.json은 *연구 frontier만*(visited/open_questions/claims_index) 담고 대화기억은 절대 건드리지 않는다 — 경계를 좁혀 흡수당하지 않고 흡수한다. 한 줄: 두뇌·대화기억=에이전트(또는 hermes), 증거·provenance·frontier=내 척추.
BRAIN_BOUNDARY: 코드로 박는 것(얕고 결정론적, 판단 0): (1) sniff — URL/확장자/매직바이트로 타입 판정만, "이게 중요한가"는 안 물음. (2) dispatch 테이블 — type→추출기 매핑, 6줄짜리 dict. (3) sha256+dedupe+verify — 순수 결정론. (4) read/write_state, append claim — I/O만. (5) cite-or-fail 게이트 — quote∈bytes, 이미 farm에 있음.
에이전트에 맡기는 것(전부 판단): (1) frontier 우선순위 — "구글 다음 홈페이지냐 틱톡이냐". (2) open_question 생성 — "이 전사에서 뭐가 빠졌나". (3) 깊이 결정 — 언제 멈추고 언제 더 파나. (4) 비정형 출현시 적응 — "정형 표 보다 이미지가 핵심이네" 판단 후 ingest(image) 호출. (5) 인사이트 추출·claim 문장. (6) 교차일치 판단.
경계선 원칙: 코드는 *명사*(artifact, frontier entry, claim)를 영속화하고, 에이전트는 *동사*(고르다, 묻다, 멈추다, 적응하다)를 수행한다. gyeongju 오탐 교훈을 규칙으로: 어떤 임계값도 transcript/artifact 내용을 *버리거나 죽이지* 않는다 — 코드는 라벨링·영속화만, 폐기 결정은 에이전트.
OBJECTION: 최대 리스크 두 가지. (1) content-addressed id가 "정체성"이라는 전제가 *준안정 추출기*에서 깨진다: refextract는 ffmpeg scene-threshold·whisper 비결정 빔서치를 쓰므로 같은 URL을 두 번 ingest하면 프레임 바이트·전사 텍스트가 미세하게 달라 sha256이 갈리고 → dedupe가 실패해 "같은 영상"이 두 행이 된다. 즉 해시-dedupe는 *원자 다운로드*(같은 바이트)엔 완벽하나 *파생 산출물*엔 거짓 신규를 만든다. 완화: dedupe 키를 두 층으로 — 원본은 sha256(bytes), 파생은 (source_url+extractor+params) 논리키를 별도 기록해 visited에서 스킵. 해시는 변조방지용으로만 신뢰하고 dedupe는 source_url 기반으로 내린다. (2) 더 깊은 반론: 이 척추는 hermes의 SessionDB가 이미 하는 일(영속·재개·cross-session)의 90%를 빈약하게 재발명할 위험. frontier/provenance만이 진짜 신규다. 그러므로 척추를 *독립 프레임워크로 키우지 말고* hermes/Claude-skill의 plug-in 증거레이어로 좁게 못박아야 흡수당하지 않는다 — 욕심내면 진다.
DO_NOT_BUILD: (1) frontier 우선순위 함수·점수식·임계값 결정트리 — gyeongju 오탐의 재발. "다음에 뭘 볼지"를 코드가 정하면 그 순간 멍청해진다. (2) state.json에 대화로그/메시지/토큰회계 — hermes SessionDB와 정면중복, 100% 진다. 연구 frontier만. (3) 새 claim-gate 재구현 — farm claim-gate.ts가 이미 cite-or-fail이다, 호출하거나 quote∈bytes 미니버전만. (4) ToS 위반 ingest 경로 — TikTok/IG 자동취득·쿠키·anti-bot 우회 추출기. sniff가 그런 URL을 만나면 에이전트에게 "수동/합법경로로" 반환만. (5) 동시 대형모델 로드(easyocr+large-v3+medium) — refextract가 이미 subprocess+gc로 피한 OOM을 ingest 오케스트레이션이 되살리지 마라; ingest는 추출기를 *순차* 호출. (6) 새 무거운 의존성 — sqlite-vec/임베딩/벡터DB로 frontier를 "스마트"하게 만들려는 유혹. JSONL+에이전트면 충분, $0 유지. (7) raw 산출물 hoarding — ledger엔 sha256+content_path만, 원본 비디오/오디오는 삭제(don't-hoard 유지).

## productive
THESIS: 빠진 것은 brain도 framework도 아니라 *디스크 위 공유 작업기억* 하나다. 그것을 가장 작게 출하하라: refledger.py(stdlib, ~200줄) + research/<goal>/{ledger,findings,frontier}.jsonl + RESEARCH_RUNBOOK.md. 라우팅은 얕게(타입→추출기 dispatch)만 코드로, 전략·적응·종합은 전부 에이전트에 맡긴다.
VS_HERMES: hermes_state.py는 *대화/세션 상태*(메모리 nudge, FTS5 세션검색, Honcho 유저모델)를 영속화한다 — 에이전트를 똑똑하게 keep하는 것. 내 척추가 영속화하는 것은 *조사 산출물의 출처사슬*(무엇을·어디서·해시·언제 모았고, 어떤 주장이 어느 바이트에 앵커됐나) — 결과를 신뢰가능하게 keep하는 것. 직교한다. 차용: ledger/findings/frontier를 hermes처럼 단일 append-only jsonl + 인간가독 .md 미러(MEMORY.md 패턴)로 두는 *형식*은 그대로 빌린다(검증된 좋은 형식, 재발명 금지). 중복 아님: hermes에 provenance가 *없다*는 건 WebFetch로 실제 repo 구조(hermes_state.py/skills/agent/providers, closed learning loop, FTS5, Honcho — citation/evidence-ledger 모듈 0개) 확인됨. 흡수위험: 낮지만 0은 아니다. hermes가 "provenance 필드 하나 추가"하면 ledger 흉내는 흡수된다. 흡수 불가능한 건 *farm의 cite-or-fail 게이트가 미인용 주장에 run을 실패시키는 강제력*과 *상류 coverage_gate가 캡처 전에 환각을 라벨링하는 것* — 이 둘은 hermes에 plugin 하나로 안 들어온다(별도 검증 TCB가 필요). 그러니 척추 자체로 차별화하지 말고, 척추를 farm 게이트로 *가는 입구*로 포지셔닝하라.
BRAIN_BOUNDARY: 코드(refledger.py, ~200줄 stdlib)가 하는 *전부*: (1) ingest(thing): 타입 감지(.mp4/.webm→video, .png/.jpg→image, http*&html→html, http*&json/api→api, .vtt→transcript, else→text) → 얕은 dispatch(video→refextract.py subprocess, image→refocr.py subprocess, html→urllib fetch, api→urllib+json, transcript→그대로 등록, text→그대로) → 산출물 해시 → ledger append → Artifact dict 반환. (2) record_finding(text,label,anchor) → anchor.artifact가 ledger에 있는지 확인 후 findings append. (3) frontier_open/close/note → frontier append. (4) frontier_state() → frontier.jsonl reduce해서 {open:[...], closed:[...], visited:set} 반환. (5) verify() → 모든 findings anchor가 등록됐나 + ledger 해시 재계산 일치하나. (6) digest() → SUMMARY.md 생성. *그게 끝*. 임계값·점수·결정트리 0개.
에이전트(Claude Code 두뇌)가 하는 전부: 무슨 데이터가 필요한지, 어느 소스부터, 구글→홈페이지→세부 사고흐름, 정형 파다 비정형 만나면 frontier에 뭘 open할지, 어떤 finding이 OBSERVED인지, 언제 farm 게이트로 봉인할지, 언제 그만둘지. 즉 *모든 판단*. 경계선의 리트머스: "이 결정이 영상/주제마다 달라지나?" → 그렇다면 에이전트(코드 금지). degeneracy()가 코드에 남는 *유일한 예외*인 이유는 그게 판단이 아니라 측정된 결정론적 사실(반복루프=garbage)이기 때문 — 그래서 그것조차 refrecord 안에 격리돼 있고 척추엔 안 들어온다.
OBJECTION: 최대 리스크 둘. (1) **verify의 cite-or-fail은 farm 게이트의 약한 복제다 — 가치 의문.** refledger.verify는 "anchor가 등록됐나 + 해시 일치하나"만 본다. 이건 farm claim-gate.ts가 이미 하는 일(citation registered + sha256 재해시)의 부분집합이고, farm처럼 *바이트 안에 quote가 실제 있나*(normalizeForMatch 포함검사)까지는 안 한다. 그러니 verify는 'farm 가기 전 로컬 사전점검'으로만 정당하고, 그 이상으로 키우면 farm과 중복·표류한다. 정직한 답: 척추의 verify는 일부러 얇게 두고, 진짜 봉인은 farm에 위임한다(refledger.verify는 dangling/tamper만, 의미검증은 farm). (2) **ingest의 타입라우터가 두 번째 degeneracy()가 될 위험.** "video면 refextract, html이면 fetch"는 지금은 얕지만, 한 번 라우터를 코드에 두면 "유튜브면 자막 우선, 틱톡이면…, 페이월이면…" 하는 특수분기가 기어들어와 결국 gyeongju 오탐처럼 부서진다. 방어: ingest는 *확장자/스킴*만 보고 dispatch하고 *내용 기반 분기 절대 금지*. 소스별 전략은 런북 산문에. 그리고 가장 근본적 반론: cite-or-fail(farm이든 척추든)은 fabrication-at-capture(모델이 환각 전사를 바이트로 박음)를 못 막는다 — 전 세션 합의. 척추는 '신뢰가능'을 *출처추적가능·재현가능·앵커됨*으로 정의할 뿐 '정확함'은 보장 못 한다. 정확함의 유일한 상류 방어는 refrecord의 coverage_gate(캡처 전 NO_SPEECH/DEGENERATE 라벨)이고, 척추는 그 라벨을 ledger.note에 보존해 내려보낼 뿐이다.
DO_NOT_BUILD: 만들면 안 되는 것: (1) 새 오케스트레이터/런타임/이벤트루프 — _arch2_workflow.mjs 같은 workflow 엔진을 조사용으로 짓지 마라. 두뇌는 Claude Code 루프다. (2) ingest 안의 내용기반 분기·점수·임계값(유튜브특수/틱톡특수/품질점수) — gyeongju 퇴화 오탐의 반복. 확장자/스킴 dispatch만. (3) farm 게이트의 풀 복제(quote 포함검사·corroboration·Merkle) — verify는 dangling+tamper만, 의미·봉인은 farm 위임. (4) hermes식 learning-loop/skill-자가개선/FTS5 세션검색/유저모델 — refcap은 개인·$0·중립, 그건 hermes의 몫이고 우리 조사신뢰성과 직교. (5) frontier를 *상태머신*으로(전이규칙 코딩) — append-only event log + reduce만, 전이판단은 에이전트. (6) 자동 yt-dlp/쿠키/anti-bot 우회를 ingest에 — ToS회색은 refauto 단일 진입점에 격리 유지, ingest는 명시 입력만. (7) raw 비축 — refextract의 don't-hoard(audio.wav/vocals.wav 삭제) 그대로, ledger는 해시+경량 산출물만 KEEP. (8) 새 의존성 — stdlib만; OCR/whisper/demucs는 이미 있는 subprocess 호출로만 닿는다(동시 대형모델 로드 금지=15GB OOM 회피, refextract의 OCR-subprocess 격리 패턴 준수).


# ===== SYNTHESIS =====

## design_philosophy
확정 사상 한 줄: "두뇌를 코딩하지 마라 — 빠진 건 brain도 framework도 아니라, 에이전트의 결정을 디스크에 묶는 얇은 SPINE(공유 작업기억 + 증거게이트로 가는 입구)이다." 4부로 확정. (B)두뇌=Claude Code 루프(또는 hermes). 전략·라우팅·종료·적응은 전부 여기. (T)도구=이미 있는 추출기(refextract/refocr/refrecord/fetch). (S)척추=research/<goal>/ 아래 append-only JSONL 3종(ledger=만진 바이트+provenance, findings=insight+앵커, frontier=재개용 탐색이벤트) + farm 게이트로 가는 다리. (L)루프=ReAct, 에이전트 주도, 코드 아님(RUNBOOK.md 산문). 핵심 통찰(4렌즈 공통, gyeongju 오탐이 증거): 코드는 "거짓말을 못 하게"(존재·불변·캡처품질의 결정론적 판정)만, 두뇌는 "무엇을 조사할지". 사용자 불만("스킬에 두뇌가 없어")의 정확한 진단 = 두뇌 추가가 아니라 refauto의 직선성(url 하나→extract 하나→끝, 27줄·check=False·goal/루프 없음)을 푸는 것. 추출기를 멱등 호출가능하게 열고, 에이전트가 N번 호출하며 결과를 manifest에 누적하면 두뇌(에이전트)가 알아서 깊이 판다. "정형 중 비정형 출현"의 답 = 코드 분기가 아니라 에이전트가 다음 추출기를 고르고 frontier에 한 줄 append하는 것(적응은 두뇌, 기록·재개는 척추).

## architecture
refcap 쪽(farm 밖·중립)에 stdlib-only 단일 CLI `refledger.py`(~200줄)를 추가해 research/<slug>/ 디렉터리 아래 3개 append-only JSONL을 관리한다: ledger.jsonl(content-addressed: id=sha256[:16], type/source/method/path/sha256/ts/provenance — 같은 바이트면 dedupe, 변조시 재해시로 detect), findings.jsonl(text/label(OBSERVED|INFERRED|UNKNOWN)/anchor{artifact_id,locator}/confidence — anchor.artifact_id가 ledger에 없으면 거부=로컬 cite-or-fail의 얇은 층), frontier.jsonl(op:open|close|visit|note / item / kind:unstructured|semi|structured|question / reason — reduce로 재개상태 도출). 라우팅은 얕은 dispatch만(확장자/스킴→추출기, video→refextract subprocess, image→refocr subprocess, html→urllib, api/json→urllib+json, transcript(.vtt)→그대로, text→그대로) — 내용기반 분기·점수·임계값 0개. 두뇌(전략·우선순위·종료·적응)는 에이전트. 척추는 무상태가 아니라 "결정의 기억"만 영속화. 고가치 finding은 verify 통과 후 기존 farm 도구(farm_register_evidence/transcript → farm_add_claim → farm_run_claim_gate)로 봉인 — refledger는 farm을 import 0(중립 유지). 제약: stdlib만(신규 의존성 0, $0), 한글경로-safe(ascii 해시 prefix 디렉터리 + json ensure_ascii=False + utf-8, refextract L80-87/L108-109 패턴 답습), 추출기 순차 호출(동시 대형모델 로드 금지=15GB OOM, refrecord L130-132 gc 패턴), don't-hoard(raw 비디오/오디오 미복사, 해시+경량 추출물만 KEEP — refextract L98-102 답습).

## vs_hermes_positioning
포지셔닝 확정(4렌즈 합의 + 코드검증): "두뇌=에이전트"는 차별점이 아니라 입장권(table stakes) — hermes(LLM loop+skills+state)도 deep-research류(이 repo 번들된 deep-browser-research)도 이미 두뇌를 코딩 안 한다. 차용(짓지 마라, 위임): hermes_state.py(세션상태)+FTS5 세션검색+LLM요약 cross-session recall+Honcho 유저모델+agentskills.io skills는 "대화·세션 기억"에서 내 척추보다 압도적으로 성숙. 내 frontier는 그 얇은 버전이 맞으니 대화기억은 절대 재구현 안 함. 직교(중복 아님): 내 척추가 영속화하는 건 "조사 산출물의 출처사슬"(무엇을·어디서·해시·언제 모았고 어떤 주장이 어느 바이트에 앵커됐나) — hermes의 audit는 *학습용 trajectory 압축*이지 검증증거가 아님(README/소스에 provenance/cite-or-fail 모듈 0개, 1차확인). 차별(durable): hermes에 *구조적으로 없는* ① 결정론적 cite-or-fail 게이트(claim-gate.ts L386 byte-grounding, LLM 호출 0, deps 거의 0), ② 상류 coverage_gate(refrecord: 음향통계로 NO_SPEECH/DEGENERATE를 캡처 *전*에 라벨 — 모델출력을 *불신*), ③ Merkle 번들 제3자 재검증(farm_verify_bundle), ④ capture-binding(capture_transcript binds:{path,sha256}). 흡수위험(정직): hermes가 "도구출력마다 sha256+source_url+인용검사기"를 붙이면 ledger층 80%는 흡수됨 — 인정. 흡수 *안 되는* 20% = 기능이 아니라 *아키텍처 입장*: 작은 TCB+중립성(검증자가 두뇌를 신뢰할 필요 없음)+bind-at-capture. 단 이 20%조차 origin-bound capture는 소켓/OS레벨 플랫폼이 더 잘함(전 세션 합의) → 유일하게 진짜 durable = "중립적·작은·외부감사가능한 검증커널"이라는 포지션 자체. 전략결론: 척추로 hermes와 *기능경쟁 금지*. refcap을 agentskills.io 표준 skill로 만들어 hermes/Claude Code 두뇌+기억 *위에 plug-in되는 증거레이어*로 좁게 못박는다(경쟁이 아니라 보완). STOP 신호: state/memory/skill을 자체 구현하거나 "누가 sha256 붙이나"로 싸우기 시작하면 이미 졌다 — 싸움터를 "bind 시점 + TCB 감사가능성"으로 옮긴다.

## spine_concrete
파일: C:\Users\이지범\refcap\refledger.py (신규, stdlib만: hashlib,json,os,sys,subprocess,urllib.request,uuid,datetime,argparse). 위치: refextract가 이미 쓰는 here/refs/ 와 형제로 here/research/<slug>/.

INGEST (얕은 라우터, 두뇌 0):

  ingest(rdir, thing, note="")->dict  # detect_type→dispatch: video→subprocess refextract.py→refs/<name>/ 폴더를 1행 등록; image→subprocess refocr.py --frames; html→urllib GET→art/<id>.html + 추출 visible text; json/api→urllib GET→art/<id>.json; transcript(.vtt)→그대로 등록; text→그대로. 실패시 {"error":...}(refextract 패턴). LEDGER (refextract L107-109 사이드카를 표준스키마로 승격, 신규 아님):
  ledger_append(rdir, **row)->dict  # id="a_"+sha256(content)[:16]; 이미 있으면 append 안 하고 기존 행 반환(dedupe). 한 줄={artifact_id,sha256,type,source,method,path,ts,note,provenance}. raw 미복사(don't-hoard), refs/<name> 산출물은 path로 참조만.
  verify(rdir)->dict  # {ok,dangling_anchors[],hash_mismatch[]}: 모든 findings.anchor.artifact_id가 ledger에 있나 + ledger 각 path 재해시==기록 sha256. 일부러 얇게(farm 게이트의 약한 사전점검; quote∈bytes 의미검증은 farm에 위임).

FINDINGS (refextract의 OBSERVED/INFERRED/UNKNOWN 규율을 구조화):
  record_finding(rdir,text,label,artifact_id,locator,confidence="med")->dict  # artifact_id 미등록이면 raise. anchor.locator=ts=12.4|frame=hook_02.jpg|char=120..180|cue=00:12. farm_add_claim 입력으로 1:1 승격.

FRONTIER (frontier-as-data, 상태머신 아님):
  frontier_open/close/note(rdir,item,kind,reason); frontier_state(rdir)->dict  # jsonl reduce→{open[],closed[],visited[]}. 코드는 영속화·reduce만, pop/우선순위는 절대 안 정함.

DIGEST: digest(rdir)->str  # SUMMARY.md(ledger표+OBSERVED findings+open frontier, ensure_ascii=False).
__main__: argparse 서브커맨드 open|ingest|finding|frontier|state|verify|digest → 에이전트가 Bash로 한 줄씩.

## honest_limits
100% 아닌 이유(정직): (1) cite-or-fail은 *hallucination-at-cite*(인용 없는 주장)만 막고 *fabrication-at-capture*(모델이 환각 전사를 register_transcript로 박음)는 못 막는다 — claim-gate.ts L575 normalizeForMatch는 lowercase+whitespace만, L386 includes()는 "인용텍스트가 등록바이트에 존재"만 증명하지 "그 바이트(전사)가 정확"은 증명 못 함. 환각도 등록바이트 안에 있으면 게이트 통과(전 세션 합의). 정확함의 유일한 상류방어 = refrecord coverage_gate(캡처전 NO_SPEECH/DEGENERATE 라벨), 척추는 그 라벨을 보존만. (3) ledger 80%는 hermes가 "도구출력마다 sha256+source_url+인용검사기" 붙이면 흡수됨 — 살아남는 20%는 기능이 아니라 아키텍처 입장(작은 TCB+중립성+bind-at-capture)이고, 그 bind-at-capture조차 origin-bound capture attestation은 소켓/OS레벨 플랫폼이 더 잘함 → refcap의 durable moat는 "검증커널 제공"이 아니라 "중립적·작은·외부감사가능"이라는 포지션. (6) "정형 중 비정형 흡수"는 *코드가 흡수*가 아니라 에이전트가 다음 추출기를 고르는 것 — ingest에 적응로직 넣으면 안 됨. (7) ToS: TikTok/IG 자동취득·쿠키·anti-bot 우회 안 함; ingest는 이미 서빙된 것/공식API/사용자제공 파일만, yt-dlp는 refauto 단일진입점에 격리.
